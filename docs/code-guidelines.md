# 设计与代码维护指南

补充 [AGENTS.md](../AGENTS.md) 的规则说明与示例。

## 设计与模块边界

按实际变化原因划分职责：业务规则变化不应迫使 UI 或数据访问逻辑一起修改。只有当前需求需要扩展点时，才引入策略、插件或额外分层。

```javascript
// 业务判断接收数据；入口读取页面状态并更新 UI。
function canEdit(user, article) {
  return user.id === article.authorId;
}

editButton.disabled = !canEdit(currentUser, currentArticle);
```

修改依赖关系时，沿新增导入检查是否存在返回当前模块的路径；共享模块不得导入页面模块，也不得从全局读取页面私有状态。调用方只通过公开接口操作，不能因对象可访问就直接修改其内部字段。

## 复用与抽象

同一业务规则在多个位置需要同步修改时，提取共享实现；外形相似但变化原因不同的代码可以保留重复。

例如，多个入口校验同一种项目标识，可以共享 `parseProjectId(value)`；权限、分页和错误策略不同的两类搜索，应分别实现，避免合并成带多个模式开关的 `search(options)`。

## 状态与生命周期

每份状态只有一个权威来源，派生值按需计算。例如，购物车总价由条目计算，不与条目分别维护；若性能需要缓存，必须明确失效和更新位置。

异步操作覆盖成功、失败、取消和销毁后的处理。搜索框连续请求时，取消旧请求以释放资源，并在写入状态前检查请求是否仍有效，防止旧结果覆盖新结果；失败结果同样需要检查，避免旧错误覆盖新状态。组件销毁时使未完成结果失效，并清理请求、监听器和定时器。

新增资源时，同时确定释放位置：监听器对应移除或 `AbortSignal`，定时器对应清除或一次性执行结束，订阅对应取消订阅。页面或组件存活期间的资源可持续运行，销毁后不得残留；生命周期由框架管理时，使用其清理机制。

## 可读性与认知复杂度

认知复杂度关注理解控制流的难度。这里用两条简化限制控制复杂度，不计算专门分数；**新增或修改时检查整个函数**，嵌套函数和回调各自检查。

| 限制                      | 统计口径                                                                                                                                             |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 嵌套 **≤3 层**            | 函数体为第 0 层；进入条件、循环、`switch`、`catch` 主体增加 1 层；`else if` 与首个 `if` 同层，`case` 不额外增加层级                                  |
| 控制流语句合计 **≤10 个** | 每个 `if`（含 `else if`）、`switch`、`for`（含 `for...in/of`）、`while`、`do...while`、`catch`、三元表达式各计 1 个；`else`、`case`、`return` 不另计 |

超限时，用卫语句减少嵌套，或提取职责明确的函数；保持求值顺序、副作用、错误处理和资源释放行为一致。

```javascript
// 卫语句让正常流程顺序展开：嵌套 1 层，控制流语句 3 个。
function process(user) {
  if (!user) return '拒绝访问';
  if (!user.active) return '拒绝访问';
  if (user.role !== 'admin') return '拒绝访问';
  return '允许访问';
}
```

## 维护与验证

样式问题先定位原规则并修改，避免追加高优先级选择器叠加覆盖。删除或改名后搜索旧标识，逐项处理残留的调用、样式、配置和文档；移除导出或依赖前检查仓库内引用及约定的外部入口。

验证覆盖变更风险：业务逻辑检查正常与边界输入，异步逻辑检查失败、取消和结果乱序，UI 检查实际交互与响应式布局。测试验证可观察行为，不复述内部实现。

仓库检查命令：`npm test`、`npm run format:check`、`npm run build`；构建包含类型检查，也可用 `npm run typecheck` 单独执行。类型检查已启用未使用局部变量和参数检查；未使用导出、依赖及生命周期仍需结合引用搜索和代码审查确认，不能用构建通过代替。文档另检查链接与示例准确性。

完成时简要报告实际检查结果及未完成项。发现失败先修复；若被既有问题或环境阻塞，明确说明位置与原因，不能以跳过检查、关闭规则或删除有效测试来达标。
